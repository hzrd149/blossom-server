**As a** Blossom server maintainer, **I want to** reject encoded upload envelopes before authentication or body processing, **so that** only raw Blossom blob
bytes enter the existing upload/media pipelines.

</objective>

<threat_model>

## Trust Boundaries

| Boundary                                                    | Description                                                                                |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| HTTP request metadata/body → envelope admission             | Untrusted method, path, headers, auth, and streaming bytes arrive before route processing. |
| Envelope admission → BUD-11 auth and upload/media pipelines | Only acceptable raw representations may continue; the gate must not become an auth bypass. |
| Rejected request stream → runtime resource lifecycle        | Rejection owns cancellation and must not pull or buffer attacker-controlled bytes.         |

## STRIDE Threat Register

| Threat ID       | Category               | Component                           | Severity | Disposition | Mitigation Plan                                                                                                                                                                                         |
| --------------- | ---------------------- | ----------------------------------- | -------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-01-05         | Tampering              | `envelopeAdmissionMiddleware`       | high     | mitigate    | Exact D-01 method/path map and D-03 base-MIME classifier reject wrapper representations before hashing/storage; unit plus all-surface E2E verification.                                                 |
| T-01-06         | Elevation of Privilege | middleware order in `src/server.ts` | high     | mitigate    | Invalid envelopes alone short-circuit; every accepted request calls `next()` and reaches unchanged explicit route auth. Malformed-auth precedence and raw-body compatibility tests cover both branches. |
| T-01-07         | Denial of Service      | rejected PUT body                   | high     | mitigate    | Await `ReadableStream.cancel()` before 415 and use an instrumented stream that fails on pull, proving no drain/buffer/worker dispatch.                                                                  |
| T-01-08         | Information Disclosure | `X-Reason` response header          | low      | mitigate    | Use a fixed ASCII-only human guidance string and assert actual response-header construction on every surface.                                                                                           |
| </threat_model> |                        |                                     |          |             |                                                                                                                                                                                                         |
